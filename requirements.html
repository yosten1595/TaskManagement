この書類で使う言葉の解説

パソコン操作に慣れていない方のために、この書類で繰り返し出てくる言葉を事前に説明します。

📋ボード
プロジェクトや用途ごとに作る「作業スペース」。例えば「ECサイト開発」「日常タスク」のように使い分ける。アプリを開いたホーム画面に一覧で並ぶ。
🗂️カンバンボード
付箋をホワイトボードに貼り並べて進捗を管理する手法をデジタル化したもの。タスクを「未着手」「進行中」「完了」などの列に並べて、状況を一目で確認できる画面。
📑リスト（列）
カンバンボードの中にある縦の区切り。「未着手」「進行中」「完了」などの状態を表す。自由に追加したり名前を変えたりできる。
🃏カード
リストの中に並ぶ一つひとつのタスク（やること）。付箋1枚に相当する。タイトル・期限・優先度・チェックリストなどの情報を持つことができる。
📝詳細モーダル
カードをクリックすると画面の上に重なって表示されるウィンドウ。カードの詳しい情報（説明・期限・チェックリストなど）をここで編集する。「モーダル」＝「画面に重ねて表示する窓」のこと。
🖱️ドラッグ＆ドロップ
マウスのボタンを押したままカードを別の列へ移動させる操作。例えば作業が終わったカードを「進行中」から「完了」列へ移すときに使う。スマートフォンでは指でなぞる操作にあたる。
00

現状の課題と、このアプリが解決すること

多くの企業では、タスク管理を付箋・ホワイトボード・PC のメモ帳で行っています。これらには以下のような共通の課題があります。

現状（付箋・メモ帳での管理）
  • ✗期限が近づいても誰も気づかず、作業が遅延する
  • ✗どのタスクが急ぎなのか、優先度が一目でわからない
  • ✗タスクの中の細かい作業（サブタスク）が管理できない
  • ✗プロジェクトが増えると情報が混在して見つけにくい
  • ✗現在の進捗状況をチーム全体で共有しにくい
TaskBoard を使うと
  • ✓期限が近づくと自動で色が変わり、見落としゼロへ
  • ✓優先度・ラベルでタスクの重要度が一目でわかる
  • ✓カード内のチェックリストでサブタスクと進捗を管理
  • ✓プロジェクトごとにボードを分けて整理できる
  • ✓カンバンボードで進行状況をチームで即座に共有

プロジェクト概要

アプリ名
TaskBoard（タスクボード）
目的
個人・小規模チームのタスクを視覚的に管理し、期限・優先度・進捗を一目で把握できるカンバン型ツールを提供する。
主要ユーザー
個人の作業管理から2〜10名規模のチームまで対応する汎用型。
提供形態
シングルページ Web アプリ（React フロントエンド + Spring Boot REST API）
データ保存
サーバー側の PostgreSQL に保存。

ER

データモデル（ER 図）

PostgreSQL に保存するテーブルとその関係。「07. データ機能（CRUD仕様）」のフィールド定義を、RDB 向けに正規化したもの。PK＝主キー、FK＝外部キー、線上の 1 と N は 1 対多を表す。

  • 並び順：配列（listIds / cardIds）ではなく、lists.position・cards.position 列で持つ。
  • カスケード削除：ボード削除でリスト・カードも削除（DF-04）、リスト削除でカードも削除（DF-08）。ラベル削除時は card_labels / template_labels の紐付けも削除（DF-19）。
  • ラベル・チェックリスト：カードとラベルは多対多（card_labels）。チェックリストは check_items に分離。テンプレートも同様で、テンプレート側の項目は未完了でコピーするため done を持たない。
  • 値の制約：priority は high / mid / low / NULL、due_date は NULL 可、warn_days の既定値は 3。
  • ユーザー・認証に関するテーブルは現時点の要件に含まれないため設けない（単一ユーザー前提）。
UI

画面の振る舞い（確定事項）

開発中に確定した、カード表示と編集の振る舞い。機能要件（3.4 期限・警告機能、3.6 チェックリスト機能）の具体的な動作を定める。

UI-1 期限の表示
カードの状態表示色
期限が今日より前期限 YYYY-MM-DD（期限切れ）赤
期限の warnDays 日前から当日まで期限 YYYY-MM-DD（期限間近）黄
上記より先期限 YYYY-MM-DD（余裕あり）緑
期限なし（完了リスト以外）期限を表示しない—
「完了」リストにあるカード期限あり: 期限 YYYY-MM-DD（完了）／期限なし: 完了灰（警告色にしない）
  • 色だけに頼らず、状態を文字でも示す（アクセシビリティ）。
  • 期限の状態は、表示のたびに現在の日付と所属リストから算出する。カードを「完了」リストへ移すと「完了」表示になり、To Do・進行中へ戻すと自動で「期限切れ」等の表示に戻る（保存データは変わらない）。
  • 「完了リスト」は、タイトルが「完了」のリストで判定する。
UI-2 チェックリストの編集
  • カード編集フォームで、項目の追加・チェックの切り替え・削除ができる。
  • 編集中の変更はフォーム内だけで保持し、「保存」を押したときだけデータベースに反映する。「キャンセル」した場合は、チェックした内容も含めてすべて破棄する。
  • 保存の途中で失敗した場合は、エラーを表示し、データベース上の最新の状態に表示を合わせる。
08

技術スタック

⚛️
フロントエンド：React 19.3.1 ＋ TypeScript 6.0.3 ＋ Vite 8.3.5
コンポーネント単位でボード・リスト・カードを構築。Next.js は対象外（SPA 構成）。ビルドは Vite。画面遷移は React Router 7.18.4、Lint は Oxlint 1.89.0、Node.js 24（LTS）で動作確認。
☕
バックエンド：Java 25（LTS）＋ Spring Boot 4.1.1
REST API を提供（JSON 形式・camelCase、ID は UUID、日時は UTC の ISO 8601、エラーは HTTP ステータスコード＋Spring 標準のエラー JSON。詳細は README の「API 形式」）。永続化は Spring Data JPA（Hibernate）、ビルドは Gradle 9.8.1（Gradle Wrapper）。Web・JPA・Validation・Actuator の各 starter、Lombok、PostgreSQL JDBC ドライバを使用（バージョンは Spring Boot の依存管理に従う）。
🐘
データベース：PostgreSQL 18
ボード・リスト・カード・テンプレート等を永続化。ローカル開発は Docker Compose（postgres:18 イメージ、ホスト側ポート 5433）で起動。
📌
ツールのバージョン方針
各ツールは常に安定版の最新を使用し、LTS があるもの（Java）は最新 LTS を使用する。パッチ番号は構築時に公式サイトで確認し、本セクションに実際に採用したバージョンを記載する（フロントエンドは package-lock.json、バックエンドは build.gradle・gradle-wrapper.properties が正）。
🔀
ソースコード管理：Git ＋ GitHub
ソースコードのバージョン管理に Git、リモートリポジトリの共有・レビューに GitHub を使用する。
